# 治理入口

## 1. 权威顺序

共用规则只在中央维护。

### ❌ 错误做法 / 反面教材

让项目文件覆盖组织规则。

```text
项目规范 → 覆盖中央门禁
```

### ✅ 正确做法 / 规范范例

按机器合同与中央规则裁决。

```text
机器合同 → 共用规范 → 项目边界 → 项目说明
```

详见 `01_SHARED_GOVERNANCE.md`。

## 2. 合并与发布

无可信证据不得进入正式执行链。

### ❌ 错误做法 / 反面教材

审查建议替代合并许可。

```text
智能体审查 → 直接发布
```

### ✅ 正确做法 / 规范范例

中央检查通过后再证明主分支。

```text
安全检查 + 持续集成证据 + 合并请求策略
          → validate-merge → 合并
          → 主分支来源证明 → 发布/部署
```

## 3. 文档查阅

按任务读取唯一权威文件。

### ❌ 错误做法 / 反面教材

复制多个版本的共用规范。

```text
业务仓库甲/命名规范.md
业务仓库乙/命名规范.md
```

### ✅ 正确做法 / 规范范例

统一引用中央文档。

```text
命名 → 03_NAMING_CONVENTIONS.md
变更 → 04_CHANGELOG_CONVENTIONS.md
接入 → 05_INTEGRATION_GUIDE.md
发布 → 06_RELEASE_DEPLOY_GUIDE.md
主分支 → 07_MAIN_WRITE_GUARD.md
```

完整索引见 `README.md`。
