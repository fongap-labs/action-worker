## 中央策略可确认的事实

- `policies/private-task-keys.json` 的 `projects` 为空：**零个已登记的私有隔离项目**。不能据此判断线上是否误配了某些变量或密钥值。
- `policies/task-secrets.json` 有九个普通任务准入条目，分布在两个来源仓库。这些普通任务准入项**不能推导出仓库可见性、运行中状态或私有隔离资格**。
- `.github/workflows/handle-task-dispatch.yml` 接收 `repository_dispatch: run-task`。其生命周期并发组按 `repository:project` 构成，并声明 `cancel-in-progress: false`；其他工作流与外部写入者是否遵循同一互斥协议尚无证据。

- 新私有隔离分支的来源校验要求固定提交、`stateful-private-v1` 能力声明以及零业务密钥准入，并要求独立项目传输密钥登记；当前无法满足空登记之外的真实项目证据。
- `scripts/task-state.ts` 的历史状态从同一中央仓库工作流生成的 GitHub Actions 工件中寻找，使用 `task-state-<sha256前32位>` 的仓库与项目组合身份；接受的运行须符合成功状态、来源工作流和 `main` 等验证条件。私有状态使用 `AW_ARTIFACT_KEY` 密封，且恢复时检查清单身份。
- 以上为仓库代码行为，不等于实际线上值、生产任务覆盖率、真实历史数据可恢复性已经验证。
